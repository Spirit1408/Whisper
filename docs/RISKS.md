## Результаты M0

R02–R04 проверены маркерами в новых журналах, отказами HTTP/SDK и трассировкой CLI. Старый журнал остаётся потенциально чувствительным. R05–R06 ограничены ручным Copy для всех получателей. R07–R08 проверены на ошибках ответа и жизненном цикле микрофона. Запись Original до LLM и лимиты PCM остаются в M1a. R12–R14 открыты в части нативного буфера, нескольких экранов, чистой Windows и успешного live Smart. Подробности по каждому стенду и остаточному риску приведены в [результатах M0](M0-RESULTS.md).

## Открытые технические вопросы

- **A.** Риск R01 закрыт для принятого [снимка M0-A](BASELINE.md). Восстановление подтвердило наличие незакоммиченных исходников, включая `src/lmstudio.py`. Для другого ПК остаётся открытым вопрос доступности всех установочных файлов. Проверка R02 для работающей версии описана выше.
- **D1/D2.** Для каких конкретных полей можно доказать неизменность адресата и диапазона, безопасно вернуть буфер, получить подтверждение доставки? Где допустим только артефакт?
- **D3/D4.** Какие флаги гарантируют нужное поведение overlay на испытанной версии Qt/Windows и какой состав EXE выдерживает чистый offline-хост?
- **M1a/M1c.** Какой предел длительности/байтов PCM, срок контролируемого завершения и фактическая граница отмены STT/LLM приемлемы на целевой машине? Как конкретная версия LM Studio обозначает полное завершение ответа?
- **E/M3.** Какие задержка и смысловые потери приемлемы пользователю? Какая из имеющихся Qwen и какие параметры дают их на RTX 4070 SUPER? Имеют ли Performance/Economy измеримое отличие от Balanced?

Удаление исходных JSON и старых логов не входит в решение этих вопросов. Оно требует отдельного решения владельца.

| Риск | Результат и оставшаяся граница |

| R07, R09 · сохранность | Commit проверен отдельным читателем, включая отказ ограничения при commit и реальный SQLITE_FULL в ограниченной тестовой БД. Ошибка исходной записи оставляет текст до закрытия процесса. Неисправный диск, авария питания и восстановление из резервной копии на отдельном ПК не испытывались. |
| R08 · захват и выход | Захват ограничен при поступлении PCM. Отмена и Quit проверены при записи, STT, HTTP и commit. Принятая запись завершается. Время возврата нативного драйвера, GPU и сервера зависит от backend. В M3 остаются нагрузочные пороги и ожидающий слот. |
| R08 · выбор микрофона | Имя из конфигурации могло разрешиться в WDM-KS с неподдерживаемыми 16 кГц. На этом ПК проверен переход к системному входу и успешное открытие/закрытие обновлённым AudioRecorder. |

| R10 · поздние ответы | Проверены отмена, закрытие и скрытие артефакта во время Smart. После аварийного выхода восстанавливаются статусы, автодоставка отсутствует. Конкурирующая правка пресетов и результатов относится к M2. |
| R12–R14 · платформы | Живой Smart подтверждён. Нативная доставка/UIA и clipboard остаются в M1b/M5, мониторы — в M4, сравнительные измерения LLM — в M3, чистая Windows — в M6. |

## Остаточные риски M1b

| Риск | Наблюдение и граница |
|---|---|
| R05, R12 · фокус и получатель | Удерживаемый ITextRange исключает перенаправление текста новому полю через клавиатуру. WinEvent и повторная проверка ловят наблюдаемые изменения, включая уход и возврат фокуса в отдельном desktop. Между последней проверкой и COM-вызовом приложение-получатель может изменить исходный документ. Windows не предоставляет общей атомарной транзакции для фокуса, диапазона и записи. |
| R05 · совместимость | У Блокнота 11.2609.11.0 документ работает в другом UI-потоке. Проверка согласия потоков позволила подтвердить адресную вставку в самом редакторе. Различие поля, активного окна или PID блокирует доставку. Для иных версий сохраняется проверка свойств во время выполнения. |
| R06 · буфер | Временная подмена исключена из реализации. Номер изменения проверяется до записи. Частные MIME-данные и конкурентное копирование проверены. Нативный Copy в отдельной оконной станции остаётся ручной проверкой на этом хосте. |
| R10 · неизвестная доставка | Проверен сбой процесса после записи до подтверждения. При timeout или сбое SQLite фактический текст уже может быть в поле. UI предлагает проверить поле перед ручной вставкой, автоматического повтора нет. |
| R15 · Smart | Автоматические регрессии сохранения, отмены, fallback и доставки прошли. Владелец подтвердил ручной сценарий M1b со сменой окна. |
