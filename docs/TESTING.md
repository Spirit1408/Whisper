# Стратегия проверки

План проверок и границы приёмки приведены ниже. Фактические результаты, окружение, команды повторения и оставшиеся ручные сценарии приведены в [протоколе M0](M0-RESULTS.md). Критерии каждого [рабочего пакета](BACKLOG.md) принимаются по отчёту, который указывает версию снимка и среды, сценарий, ожидаемый и фактический исходы, повторяемость и остаточное ограничение. Использовать статусы «пройдено», «не пройдено», «не проверено» с причиной. Расчётная оценка не заменяет измерение.

## Уровни и изоляция

Для известного дефекта по возможности получить наблюдаемый отказ на снимке A до соответствующего изменения M0-B, затем повторить тот же тест на исправленной версии. При невозможности исходного прогона указать причину. Два успешных пути M0-A зафиксированы отдельно в [отчёте baseline](BASELINE.md). E1 использует исходный снимок до изменений поведения, даже если календарно измерение состоится позднее. Сравнение моделей относится к M3.

| Уровень | Среда | Что доказывает |
|---|---|---|
| Unit | Синтетические строки и короткие PCM в RAM, поддельные HTTP, CLI, часы, состояние окна/буфера. Без GPU, сети и системного hook. | Ветвления Raw/Smart, валидатор ответов, допуск задач, решение о доставке и состояние отмены. |
| Integration | Временный каталог с искусственными JSON/БД, тестовые адаптеры, контролируемые ошибки записи и остановки процесса. | Идемпотентность, порядок commit, ошибки диска, конфликты ревизий, восстановление. Проверяется и режим скрытого окна. |
| Windows | Отдельный тестовый профиль, синтетический текст, собственное контрольное поле и явно выбранные приложения. Зафиксировать версии Windows, приложения и вид поля. | Доступность UIA, поведение hotkey, overlay, clipboard и различие между dispatch и реально наблюдаемым получением. |
| Сборка | Чистая Windows без системного Python. Локальные веса подготовлены отдельно, сеть отключена. | Целостность папки EXE, наличие Qt plugins, CUDA DLL и VAD, понятный исход при отсутствии каждой зависимости. |
| Нагрузочные и модели | Только после согласования, на целевой машине с разрешённым корпусом. | Производительность, RAM/VRAM, качество редакторских режимов и предел длительности. |

На baseline импорт `main.py` открывает старый журнал. После M0-B обработчики создаются только в точке запуска. В обоих случаях тесты импортируют модули из отдельной временной копии. Все пути и backend теста должны вести в изолированную среду. Результат проверки приватности — наличие/отсутствие синтетического маркера без сохранения его окружения. Для журнала и диагностики предпочтительны разрешённые структурированные поля. Строка исключения или полный ответ сервера могут содержать вход.

Для Windows-матрицы каждая строка включает приложение/версию и тип поля, способ идентификации, разрешённое действие, поддержку выделения, формат буфера, повторную проверку и наблюдаемый исход. Начать с контролируемого текстового поля, затем нейтрального редактора, браузера и неподдерживаемого/защищённого контекста. Смену DPI и монитора проверять отдельно. Результаты эксперимента D не расширяют поддержку автоматически.

## M0-E — метод исходного измерения

1. В качестве сравниваемых версий взять согласованный снимок A и снимок после B/C. Один хост, одинаковые драйверы, частота аудио, модель STT и LLM, compute type, VAD, beam, язык, HTTP timeout, контекст, offload и доступные фоновые ресурсы. Зафиксировать только технические идентификаторы. Параметр, который backend не раскрывает, пометить неизвестным.
2. Предлагаемая малая выборка — заранее разрешённые короткие и средние тестовые фразы, например 3–5 и 15–30 секунд, RU/EN. Подавать те же PCM в обеих сериях. Отдельно фиксировать пробу через настоящий микрофон, если она разрешена. Входы принадлежат тестовому корпусу. Реальные диктовки пользователя не используются.
3. Измерять монотонными часами. Для холодного запуска считать интервал «старт процесса → готовность STT» и отдельно указывать, находилась ли LLM в памяти. Не выгружать чужие модели ради имитации холодного старта. Горячая серия начинается после прогрева.
4. Предложение для согласования нагрузки — 3 холодных старта и 10 горячих повторов на ячейку «длина × режим». При меньшей фактической серии привести сырые числовые интервалы или диапазон и размер выборки. p95 малой выборки — ориентир. Никаких целевых p95 и победителя среди моделей заранее.
5. Для каждого запроса фиксировать отпускание клавиши/конец тестового ввода, старт/окончание STT, начало/конец LLM, подтверждение записи, dispatch и событие получения **в контролируемом тестовом поле**. У исходной реализации история пишется после попытки вставки. Интервалы считать по фактическим событиям. При отсутствии маркера ставить «не измерено».
6. В отчёте по каждой серии указать число запросов и длительность аудио, успехи и отказы по категориям, p50/p95 сквозной задержки и стадий, время до доступного текста, `RTF = время STT / длительность аудио`. Показать RAM процесса и пик VRAM с методом/частотой выборки. Общая VRAM GPU включает другие процессы. Token/s включать только при доступных счётчиках backend. Чувствительные строки и полные ответы не записывать.
7. Сравнивать Raw с Raw, Smart с тем же Smart. Fallback, пропущенную доставку, timeout и неизвестный исход выводить отдельно со знаменателями. Для M0 достаточно показать повторяемую исходную оценку и отличия Safety. M3 добавляет контролируемое сравнение Qwen по скорости, смысловой точности и нагрузке.

В аудите ранее были сопоставлены интервалы из старого журнала с точностью до секунды. Исторические p50/p95 успешной редактуры около 3/10 с и 35 read timeout объясняют выбор сценариев. Они не являются измерениями по этому протоколу.

### Компактная ручная приёмка M1a

Закрыть другой экземпляр диктовки через Quit. Из корня checkout создать новый тестовый профиль, сохранив значение переменной до повторного запуска:

```powershell
$reviewProfile = Join-Path $env:TEMP ('whisper-review-' + [guid]::NewGuid().ToString('N'))
& ./.venv/Scripts/python.exe src/main.py --profile-dir $reviewProfile
```

1. В Raw выбрать рабочий вход, продиктовать тестовую фразу и проверить Original в карточке. Нажать Copy и вручную вставить в своё тестовое поле.
2. Включить уже готовую локальную Smart-модель, скрыть окно и продиктовать вторую фразу. Открыть окно из трея. Проверить результат и Open Original, если тексты различаются.
3. Выйти через Quit и повторить ту же команду с тем же профилем. Обе карточки доступны, внешнее поле сохраняет содержимое. Для отмены начать ещё одну запись, нажать Cancel dictation и отпустить клавиши. Следующий PTT доступен после завершения занятого backend.

Для возврата к M0 открыть отдельную копию checkpoint `ea78686` с прежней venv и локальными весами. SQLite и legacy-файлы сохранить. M0 читает старый JSON, новые записи остаются доступны при повторном запуске M1a с той же БД.
