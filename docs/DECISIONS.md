# Архитектурные решения

**Утверждено** — обязательное направление продукта. **Предложено** — конкретная реализация, которую предстоит принять в плане пакета. **Требует эксперимента** — выбор, для которого ещё нет достаточного измерения. Эти статусы описывают решения, а не факт выпуска функции.

| ID и статус | Решение | Основание и следствие |
|---|---|---|
| ADR-01 · Утверждено | Модульный монолит, координатор, один последовательный inference-worker, один владелец соединения SQLite, адаптеры STT и LLM. | Текущий desktop уже имеет отделимые аудио- и AI-модули. Единственный владелец переходов упрощает разбор гонок, не требует брокера или сервиса задач. |
| ADR-02 · Утверждено | Данные задачи и вычисления находятся в RAM. В SQLite допустимы минимальные метаданные и три независимых статуса. После рестарта доставка не возобновляется. | Нельзя точно определить, успел ли чужой процесс обработать вставку перед сбоем. Повтор может продублировать текст. |
| ADR-03 · Утверждено | Original неизменяем, успешный результат каждого пресета заменяем по ревизии. Повтор возможен из Original или выбранного результата. | Правка пользователя и прежний успех переживают сбой или опоздавший ответ. Постоянное версионирование всех текстов не требуется. |
| ADR-04 · Утверждено | SQLite, FTS5, транзакции и версионированная схема. История без лимита числа записей по умолчанию, корзина на 30 дней с настройкой, без аудио на диске. | Индексы и постраничное чтение поддерживают рост истории при ограниченном UI. Миграция идемпотентна. Неподтверждённый legacy Original остаётся неизвестным. Старые JSON/лог сохраняются. |
| ADR-05 · Утверждено | Доставка только сохранённого текста, по проверенной матрице. Отправка вставки и подтверждённое получение — разные исходы. | Глобальный ввод адресуется текущему фокусу. При неопределённости результат доступен человеку, новое содержимое буфера сохраняется. |
| ADR-06 · Утверждено | Сохранить Faster Whisper, LM Studio и PySide6. Общая LM Studio по умолчанию, запрет автоматической выгрузки чужих и неоднозначных экземпляров. | Имя модели не устанавливает владельца. Клиент приложения не должен прерывать другие локальные задачи. |
| ADR-07 · Утверждено | Offline-first. Подготовленные локальные ресурсы работают без внешней сети. Сетевая операция разрешается отдельно пользователем. | Кэш модели и локальный inference ещё не гарантируют отсутствие обращений библиотек к сети. |
| ADR-08 · Утверждено | Активные Raw и Smart сохраняются. M1b — стабильный Raw, M1c — стабильный продукт с обоими сценариями, M2 расширяет пресеты. | Пользователь сохраняет путь корректуры во время миграции. Временное отключение требует собственного согласования. |
| ADR-09 · Утверждено | Поставка папкой с Windows EXE/runtime без системного Python. Веса STT и LM Studio допустимы отдельно. | Позволяет проверять состав DLL, Qt plugins и VAD-ресурсов отдельно от многогигабайтных моделей. |
| ADR-10 · Утверждено как стартовая политика | Balanced, предварительно один выполняемый и один ожидающий запрос. | Приоритет — управляемая задержка и память. Большая очередь и дополнительные профили требуют измерений. |
| ADR-11 · Предложено | Первый runtime БД — пользовательский каталог, короткие транзакции, один SQLite worker, обычный журнал и полная синхронизация. | Достаточно для начальной конкуренции. Дополнительный режим журналирования оценивается при реальной нагрузке. |
| ADR-12 · Предложено | Порядок пресета — разовая команда, профиль, активный пресет. Для специализированных преобразований при отказе — сохранение без автоматической доставки. | Получателю перевода или резюме не следует автоматически отправлять текст с другим назначением. Защитные запреты выше любой настройки. |
| ADR-13 · Требует эксперимента M0-D | Первая матрица полей и буфера, окно без активации, состав EXE и поведение offline на чистом хосте. | Выбор конкретного Windows-адаптера, режим подтверждения поля и инструмента упаковки возможен после воспроизводимой пробы. |
| ADR-14 · Требует эксперимента M0-E / M3 | Границы отмены backend, целевой p95 и качество, модель по умолчанию, отличия Balanced/Performance/Economy. | Старые журналы смешивают версии и не идентифицируют успешную доставку. Контролируемое сравнение Qwen2.5-14B и Qwen3.5-9B запланировано в M3. |

Точный формат записи и переходы — в [ARCHITECTURE](ARCHITECTURE.md). Новое решение, меняющее утверждённое, требует согласования владельца и явного указания, какую запись оно заменяет.

## Применение решений в M0

Для ADR-05/06 выбран ручной Copy, пока профиль получателя не подтвердит доставку. В штатном пути отсутствует глобальная команда вставки. Для ADR-07 используются локальные веса и loopback без HTTP redirect/proxy. Отсутствие принятого результата у Smart оставляет доступный Raw. Для ADR-13 получены первые данные по UIA, Qt и переносимой папке EXE. Реальные ограничения приведены в [протоколе D/E](M0-RESULTS.md).

## Применение решений в M1a

ADR-01–05 реализованы в пределах Reliable Original. В схеме v1 один текущий результат существующего Smart на артефакт. Память удерживает неподтверждённый результат до выхода приложения. Достигнутый уровень сохранения, обработка и доставка хранятся раздельно. Для ADR-10 оставлен один активный слот с явным отказом Busy. Очередь 1+1 оценивается в M3. Предложение ADR-11 использовано для первого SQLite runtime. Предел одного захвата — 120 секунд и 16 МиБ mono float32, действует меньший из двух. На штатных 16 кГц это 7 680 000 байт. Это стартовые ограничения реализации для ревью владельцем.
