# Работа над Local AI Input Workspace

Правила действуют для всего репозитория. Общайся с владельцем по-русски. Начинай с [README](README.md), задачи в [backlog](docs/BACKLOG.md), её критериев и принятых [решений](docs/DECISIONS.md). Исторический `project.md` и локальный `CURRENT_SESSION_TASKS.md` описывают прошлые сессии.

## Рабочий цикл

**Analyze → Plan → Approve → Implement → Review → Test → Fix → Document → Checkpoint**

1. **Analyze.** Прочитай относящийся к задаче код и документы, проверь Git и существующие незакоммиченные изменения. Отдели факты от предположений.
2. **Plan.** Укажи ID пакета, цель, границы, зависимости, файлы, критерии приёмки, проверки, риск и способ отката. Сохраняй рабочие модули, если у замены нет конкретного преимущества.
3. **Approve.** Дождись явного согласования реализации пакета. Утверждение архитектуры, roadmap или текста плана само по себе не запускает разработку. При изменении согласованных границ вернись к владельцу.
4. **Implement.** Выполняй только согласованный пакет. Сохраняй пользовательские изменения и работоспособность Raw и Smart после каждого этапа. Временное отключение Smart требует обоснования и отдельного согласования.
5. **Review.** Проверь нормальный путь, отказ, повтор, отмену, гонки и границы доступа к данным, насколько это относится к пакету. Не смешивай независимые изменения.
6. **Test.** Проверь acceptance criteria по [стратегии](docs/TESTING.md). При необходимости ручной проверки зафиксируй условия, результат и то, что осталось непроверенным. Ресурсоёмкие эксперименты, установки пакетов и загрузки моделей требуют разрешения.
7. **Fix.** Исправь выявленные отклонения в согласованном объёме и повтори затронутые проверки. Открытый блокирующий критерий сохраняет статус «не принято».
8. **Document.** После каждого пакета обнови backlog и затронутую документацию. Укажи проверенные критерии, остаточные риски, отклонения и влияние на пользователя. Сверь документацию с фактическим поведением.
9. **Checkpoint.** Передай владельцу сводку изменений, проверок и способ возврата. Коммит выполняй только по явному разрешению. Checkpoint может быть принятым отчётом без коммита. К следующему пакету переходи после его согласования.

## Данные и Git

- Не удаляй пользовательские данные. Прежние `history.json`, `state.json` и `app.log` сохраняй. Проверки удаления, retention и миграций проводи на синтетических данных в изолированном временном каталоге.
- Не публикуй диктовки, промпты, содержимое сторонних окон и буфера, секреты или абсолютные персональные пути в логах, фикстурах, документах и Git. Для диагностики используй технические коды и агрегаты.
- Не выполняй destructive Git operations и не перезаписывай чужую работу. Перед согласованием коммита проверь точный список путей и содержимое предполагаемого diff, включая новые файлы.
- Внешняя сеть — только для согласованной операции. Не запускай скачивание как побочный эффект проверки. Не выгружай чужие или неоднозначно определённые экземпляры LM Studio.
- Разделяй утверждённое требование, предложенную реализацию и результат эксперимента. Завершённость пакета устанавливают проверенные критерии и фактические результаты.
